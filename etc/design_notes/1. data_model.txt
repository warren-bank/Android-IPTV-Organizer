-------------------------------------------------------------------------------- data mapping

optional user-defined value-rewrite mapping-tables
==================================================

1. m3u_channels.name     => m3u_channels.tvg_id
2. m3u_channels.tvg_name => m3u_channels.tvg_id
3. m3u_channels.tvg_id   => m3u_channels.tvg_id

notes:
  * the same mapping table can be applied to both:
      m3u_channels.name
      m3u_channels.tvg_name
  * assuming they have different values;
    otherwise, only need to process the mapping table once

optional user-defined value-rewrite string-substitution
=======================================================

1. m3u_channels.media_url
   - example:
     * original value:
         http://kytv.xyz:80/USERNAME/PASSWORD/228579.m3u8
     * static strings
         [
            "http://kytv.xyz:80",
            "USERNAME",
            "PASSWORD",
          ]
     * stored in DB as:
         %1$s/%2$s/%3$s/228579.m3u8
     * rehydrated by:
         String.format(db_url, static_strings)
   - advantages:
     * reduces size of DB by extracting duplicate strings
     * allows the user to update the static string values without needing to refresh the M3U data
       - if changing account credentials for the same IPTV service provider
       - if the IPTV service provider changes its video hosting domain
     * supports Channel URLs in the M3U file that include variations
       - example:
           http://kytv.xyz:80/USERNAME/PASSWORD/LIVE_CHANNEL_ID.ts
           http://kytv.xyz:80/USERNAME/PASSWORD/LIVE_CHANNEL_ID.m3u8
           http://kytv.xyz:80/movie/USERNAME/PASSWORD/VOD_MOVIE_ID.mp4
           http://kytv.xyz:80/series/USERNAME/PASSWORD/VOD_EPISODE_ID.mkv
   - dangers:
     * if used incorrectly (ex: removing or reordering static string values),
       then all "m3u_channels.media_url" values will become gibberish
     * if so, then the M3U will need to be refreshed
       - ie: redownloaded, and parsed using the new static string values
   - notes:
     * this is a slightly different methodology than used by my earlier app: "M3U Viewer"
         https://github.com/warren-bank/Android-IPTV-M3U-Channel-List-Viewer#settings
     * in "M3U Viewer":
       - the Channel URLs in the M3U file are edited manually prior to import
       - the "Channel URL Template" is edited manually
     * with this methodology:
       - the Channel URLs in the M3U file are input,
         and each generates its own distinct (though hardly unique) "Channel URL Template" (by replacing static strings with template variables),
         which is stored in the DB,
         and later used to rehydrate the Channel URL (by substituting static strings for template variables)
       - which is automatic,
         albeit a bit fragile to users that don't understand how to use the feature
       - of course, usage of this feature is optional:
           no static strings values => no templates => no substitution

-------------------------------------------------------------------------------- data filtering

M3U whitelists
==============
whitelist_channel_names = []
whitelist_channel_ids   = []

save = !whitelist_channel_names && !whitelist_channel_ids

if (!save && whitelist_channel_names)
  save = (
    whitelist_channel_names.includes(channel.name) ||
    whitelist_channel_names.includes(channel.tvg_name)
  )
)

if (!save && whitelist_channel_ids)
  save = (
    whitelist_channel_ids.includes(channel.tvg_id)
  )
)

if (save)
  add_channel_to_db(channel)
